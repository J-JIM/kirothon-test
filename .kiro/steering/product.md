# 맞춤 — 팀플 일정 조율 에이전트

## 한 문장
팀원 4명의 시간표와 일정을 받아 모두 가능한 회의 시간을 추천하고, 겹치는 시간이 없으면 누구에게 어떤 조정을 부탁할지 판단해 없던 시간을 만든다. 회의가 끝나면 회의록에서 다음 회의 안건과 팀원별 준비물을 뽑아 회의 전에 메일로 보내고, 프로젝트가 끝나면 팀원별 보고서를 보낸다.

## 화면 (챗봇 아님)
단계 6개: 1 팀 → 2 팀원 입력 → 3 조율 보드 → 4 계획 → 5 회의록 → 6 종료 보고서.
각 단계는 폼 + "다음 행동" 카드 하나. 오른쪽 사이드바: LLM 모드(캐시 우선/라이브) · LLM 호출 로그 · 에이전트 기록 · 수신함.
한 기기에서 4명을 탭으로 전환하며 입력한다 (팀원별 링크는 선택 기능 X1).

## 기능
- F1 첫 미팅: 에타 시간표 캡처 → LLM이 수업 블록을 읽음 → 사람이 표를 고치고 "맞아요" → 코드가 4명 모두 비는 시간 계산 → "MM-DD HH:MM에 만나면 됩니다" + 근거 3줄 + 후보 3개 → 확정 → 확정 메일 4통.
- 교집합 0: LLM이 양보안(누가 어떤 조정가능 일정을 몇 분, 어느 방향) 최대 3개 → 코드가 다시 계산해 검증 → 유효한 안만 "요청 보내기" → 요청받은 사람이 "가능(n분)/불가" → 반영 후 재계산. LLM 안이 전부 무효이거나 LLM이 실패하면 코드가 전부 열거한 안으로 대체.
- F4 회차 계획: 과제 정보(자유 텍스트) + 마감일 → LLM이 회차 수·회차별 목표·산출물·할 일 3~5개 → **날짜는 코드가** 4명 모두 비는 시간에서 회차마다 하나씩 배정(같은 날 중복 없음).
- F2 회의록: daglo·클로바노트 txt → 중점·다음주제·준비물(담당·근거문장)·기한 → 코드가 기한 안에서 다음 미팅 계산 → 팀원별 메일 미리보기 → 4통 발송 → 다음 회차 자동 확정.
- F5 진행도: 회의록과 그 회차 할 일을 맞대어 항목마다 완료·부분·미완 판정. **근거 문장이 회의록 원문에 없으면 완료로 인정하지 않는다.** 진행률과 "다음 시작점"을 메일에 넣고, 못 한 항목은 다음 회차 할 일 앞으로 이월한다.
- F3 종료: 회차 기록을 팀원별로 재구성(코드) + 포트폴리오 문장(LLM 1회, 4명분) → 코드 검증 → 보고서 메일 4통.

## 하지 않는 것
- 회의 요약 본문을 만들지 않는다. 중점·다음주제 한 줄씩만.
- 준비물을 배정하지 않는다. 회의에서 사람이 정한 것만 근거문장과 함께 옮긴다.
- 양보를 강요하지 않는다. 질문만 하고 거절도 상태에 그대로 반영한다.
- 누가 양보를 많이 했는지 개인별로 노출하지 않는다 (보고서에는 팀 전체 횟수만).
- 06:00~22:00 밖의 회의 시간을 추천하지 않는다. 장소를 추천하지 않는다.
